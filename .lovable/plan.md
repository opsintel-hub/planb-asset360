# Phase 5 — Risk Score (ตารางกลาง) + Emergency Re-balance

## ทำไมต้องมีตารางใหม่ (ยืนยันจากข้อมูลจริง)
ตาราง `claims` มี 436,141 แถว และในช่วง 90 วันมีถึง 384,409 แถว
ถ้าคำนวณสด ๆ ทุกครั้งที่เปิดหน้า จะหนักและช้า → เก็บผลสรุปไว้ในตารางกลางคุ้มกว่า
และเป็นการลงทุนครั้งเดียวที่เมนูอื่นเอาไปใช้ต่อได้ทันที

## ตารางใหม่: `public.asset_risk_scores`
สรุป "สุขภาพ/ความเสี่ยง" ของป้ายแต่ละตัว 1 แถวต่อ 1 ป้าย (คีย์ = รหัสป้าย)

| ฟิลด์ | ความหมาย |
|---|---|
| `asset_old_code` | รหัสป้าย (Primary Key, เชื่อมกับ `assets.old_code`) |
| `risk_level` | ระดับความเสี่ยง: `high` / `medium` / `low` |
| `score` | คะแนน 0–100 (ยิ่งสูงยิ่งเสี่ยง) ใช้เรียงลำดับละเอียด |
| `claims_30d` | จำนวนเคลมใน 30 วัน |
| `claims_90d` | จำนวนเคลมใน 90 วัน |
| `claims_365d` | จำนวนเคลมใน 1 ปี (ดูแนวโน้มซ้ำซาก) |
| `open_claims` | เคลมที่ยังไม่ปิด (Pending / Working On / Ready to Work / Need Reassign) |
| `last_claim_at` | วันที่เคลมล่าสุด |
| `last_pm_at` | วันที่ PM ล่าสุด (ยิ่งนานยิ่งเสี่ยง) |
| `days_since_pm` | จำนวนวันตั้งแต่ PM ล่าสุด |
| `top_problem` | ปัญหาที่พบบ่อยสุดของป้ายนี้ |
| `department` / `media_type` / `district` | ก็อปมาเพื่อกรอง/รายงานได้เร็วโดยไม่ต้อง join |
| `computed_at` / `updated_at` | เวลาคำนวณล่าสุด |

**สูตรคะแนน (ปรับได้ ไม่ใช้ AI):**
`score = 40×(มีเคลมค้างเปิด) + 25×min(เคลม30วัน,2)/2 + 15×min(เคลม90วัน,4)/4 + 10×min(เคลม1ปี,8)/8 + 10×(วันตั้งแต่ PM เทียบ 180 วัน)`
→ `high` ≥ 60 · `medium` 25–59 · `low` < 25

**อัปเดตค่าอย่างไร:** ฟังก์ชันในฐานข้อมูล `recompute_asset_risk_scores()`
คำนวณทั้งตารางในครั้งเดียวด้วย SQL (เร็ว ไม่ผ่าน browser) แล้วตั้ง cron รายวัน
ตอนดึกหลัง sync ข้อมูล + มีปุ่ม "คำนวณความเสี่ยงใหม่" ให้แอดมินกดเองได้
→ หน้าเว็บอ่านตารางนี้เท่านั้น (เบามาก) ไม่มีการเรียก AI, ไม่มีค่าเครดิตต่อการใช้งาน

## ใช้ใน Route Monitoring (Phase 5)
1. โหลดคะแนนเฉพาะป้ายที่กรองไว้ (อ่าน 1 ครั้ง cache 10 นาที)
2. จัดลำดับ: ป้ายเสี่ยงสูงเข้าวันแรก ๆ ของแต่ละคน — เปิด/ปิดด้วย toggle "จัดลำดับตามความเสี่ยง"
3. แสดง badge ระดับความเสี่ยงในรายการจุดแวะ (แผงขวา + bottom sheet มือถือ) และหมุดบนแผนที่
4. เพิ่มคอลัมน์ความเสี่ยง/คะแนนใน export CSV
5. **แผงผลกระทบเมื่อคนลา** (ใช้ toggle เดิม ไม่สร้างใหม่): เทียบก่อน/หลัง — ป้ายต่อคนต่อวัน,
   ชั่วโมงต่อวัน, จำนวนคน-วันที่เกินเพดาน 8 ชม. และบอกว่ามีป้ายเสี่ยงต่ำกี่ป้ายที่ "เลื่อนได้"
   (คำนวณจากค่าเดิมในหน้า ไม่ยิง OSRM เพิ่ม)

## นำไปใช้ร่วมกับเมนูอื่น (แนะนำตามลำดับความคุ้มค่า)
1. **Claim Aging** (คุ้มที่สุด) — เพิ่มคอลัมน์/ชิป "ความเสี่ยงป้าย" ข้างรหัสป้าย
   ทีมจะเห็นทันทีว่าใบนี้เป็นป้ายที่เสียซ้ำซาก ควรยกระดับการแก้ ไม่ใช่ซ่อมแบบเดิม + กรอง "เฉพาะป้ายเสี่ยงสูง"
2. **Asset History / ค้นหาป้าย** — การ์ดสรุปสุขภาพป้าย (คะแนน, เคลม 30/90/365 วัน, ปัญหาที่พบบ่อย, วันตั้งแต่ PM)
   ช่วยตัดสินใจว่าควรซ่อมหรือเปลี่ยนอุปกรณ์
3. **Asset Map** — ระบายสีหมุดตามความเสี่ยง + ตัวกรอง "เสี่ยงสูง" เห็นการกระจุกตัวของปัญหาเชิงพื้นที่
4. **PM Insights** — ใช้ `days_since_pm` + คะแนน จัดคิว PM ให้ป้ายเสี่ยงสูงก่อน แทนการวนตามรอบเวลา
5. **Dashboard หน้าแรก** — การ์ด "ป้ายเสี่ยงสูง X ป้าย" คลิกเข้าไปดูรายการได้

ทั้ง 5 จุดนี้ **ไม่รวมใน Phase 5** — Phase 5 ทำตารางกลาง + Route Monitoring ให้เสร็จก่อน
แล้วค่อยเลือกเสียบทีละเมนูตามที่ต้องการ (แต่ละจุดเป็นงานเล็ก เพราะข้อมูลพร้อมใช้แล้ว)

## ผลกระทบต่อการทำงาน
- เมนูเดิมทั้งหมดยังทำงานเหมือนเดิม 100% (Phase 5 ไม่แก้เมนูอื่น)
- ในหน้า Route Monitoring ทุกอย่างใหม่เป็นข้อมูลเสริม + toggle ที่ปิดได้ → ถ้าปิด ผลลัพธ์เหมือน Phase 4 เดิม
- ถ้าตารางความเสี่ยงยังไม่มีข้อมูล/โหลดไม่ได้ ระบบถือว่า "ไม่ระบุ" และวางแผนได้ปกติ
