# Asset Map & Route Monitoring — Flow การทำงาน (สำหรับนำเสนอผู้บริหาร)

เอกสารนี้อธิบาย 2 เมนู: **Asset Map** (`/map`) และ **Route Monitoring** (`/route-monitoring`)
ครอบคลุม flow ผู้ใช้ → flow ระบบ → แหล่งข้อมูล/API → สูตรคำนวณ → จุดที่เป็น AI / อัตโนมัติ → ประโยชน์เชิงธุรกิจ → แนวทางต่อยอด

---

## 0. ภาพรวมสถาปัตยกรรม

```text
MSSQL (ระบบงานเดิม)
   │  sync อัตโนมัติรายวัน (pg_cron → sync-assets / sync-pm-schedules / sync-asset-history)
   ▼
Cloud Database (Postgres + RLS)
   assets · claim_tickets · mssql_asset_history · asset_pm_schedules
   mv_pm_history · mv_pm_claim_pairs · asset_risk_scores · map_saved_routes/locations
   │  Server Function (ตรวจสิทธิ์ผู้ใช้ทุกครั้ง)
   ▼
เว็บแอป (React)  ── OSRM (เส้นทางถนน, ฟรี)
                  ── Overpass/OSM (ค้นหา POI, ฟรี)
                  ── Google Places / Street View (ผ่าน Connector)
                  ── Lovable AI Gateway (เฉพาะงานวิเคราะห์ข้อความ/ภาพ ไม่ใช่การจัดเส้นทาง)
```

หลักการออกแบบ: **การคำนวณเส้นทางและคะแนนความเสี่ยงเป็นคณิตศาสตร์ล้วน ไม่เรียก AI**
→ รันกี่ครั้งก็ได้ ต้นทุนต่อครั้ง ≈ 0

## 1. Asset Map (`/map`)

### 1.1 Flow ผู้ใช้
1. เปิดเมนู Asset Map → แผนที่โหลดหมุดป้ายทั้งหมดที่มีพิกัด
2. กรอง Project → Department (ผูกกันอัตโนมัติ) → Media Type → Zone/District
3. เลือกโหมดทำงาน 1 ใน 3
   - **POI Search** — หา "ป้ายที่อยู่ใกล้สถานที่ประเภทใดประเภทหนึ่ง" เช่น สถานีรถไฟฟ้า/ห้าง/โรงเรียน ในรัศมี 5–1000 ม.
   - **Corridor** — ลากเส้นถนน/เส้นทาง แล้วดูป้ายที่อยู่ในระยะข้างทาง (เลือกซ้าย/ขวาถนนได้)
   - **Inspection** — ปักหมุดจุดที่ต้องไป ระบบจัดลำดับการเดินทางที่สั้นที่สุดให้
4. ค้นหาสถานที่ด้วยข้อความ (เช่น "สุขุมวิท 22", "เดอะมอลล์บางกะปิ") แผนที่ซูมไปให้ทันที
5. คลิกป้าย → Popup: ข้อมูลป้าย, Street View, Mockup ภาพโฆษณา, POI ใกล้เคียง, Export
6. บันทึกจุด/เส้นทาง, แชร์ลิงก์ผลลัพธ์ให้ลูกค้าดูได้โดยไม่ต้อง login, Export CSV/GPX/KML/PPTX/PDF

### 1.2 Flow ระบบ (ทีละขั้น)
| ขั้น | เกิดอะไรขึ้น | แหล่งข้อมูล |
|---|---|---|
| โหลดหน้า | `listAssetsForMap` ดึง `assets` แบบแบ่งหน้า 1,000 แถว/รอบ, เติมพิกัดจาก `payload.LatitudeLongitude` ถ้าคอลัมน์ว่าง, สรุปรายการ Department/Media Type ให้ตัวกรอง | DB |
| โหลดสถานะเคลม | `listOpenClaimOldCodes` ดึงรหัสป้ายที่มีเคลมค้าง | DB |
| โหลดความเสี่ยง | `listAssetRiskScores` ดึงเฉพาะป้ายที่มีคะแนน > 0 (payload เล็ก) ใช้ระบายสีหมุดในโหมด Risk | `asset_risk_scores` |
| ค้นหาสถานที่ | Google Places Text Search ผ่าน Connector (คีย์อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น) | Google |
| POI Search | สร้าง query Overpass ตาม preset → **Adaptive Tiled Search**: แบ่งพื้นที่เป็นตาราง ยิงทีละส่วน กันโดน timeout, มี cache + de-dup ในหน่วยความจำ, สลับ endpoint สำรอง 3 ตัว | OpenStreetMap |
| จับคู่ป้าย–POI | คำนวณระยะทางแบบ Haversine ระหว่างป้ายกับ POI ทุกจุด แล้วเก็บ POI ที่ใกล้ที่สุดเป็น "ต้นทางของระยะทาง" ที่แสดงในตาราง/CSV | คำนวณในระบบ |
| Corridor | ส่งจุดที่ลากให้ OSRM `/route` ได้เส้นถนนจริง → หาป้ายที่ระยะตั้งฉากจากเส้น ≤ รัศมีที่เลือก → แยกซ้าย/ขวาด้วย cross-product | OSRM + คำนวณ |
| Inspection | ส่งหมุดให้ OSRM `/trip` (TSP) ได้ลำดับหยุดที่สั้นที่สุด + ระยะ/เวลาแต่ละช่วง | OSRM |
| แชร์ลิงก์ | เก็บ payload ผลลัพธ์ลง `poi_shares` พร้อม token + วันหมดอายุ อ่านผ่านฟังก์ชันเฉพาะทาง | DB |

### 1.3 สูตรหลัก
- ระยะระหว่างพิกัด: Haversine (R = 6,371 กม.)
- ระยะจากเส้นทาง: ระยะตั้งฉากจุด–เซกเมนต์ ของ polyline ที่ OSRM คืนมา
- ด้านถนน: เครื่องหมายของ cross-product ระหว่างเวกเตอร์ทิศทางถนนกับเวกเตอร์ไปยังป้าย

## 2. Route Monitoring (`/route-monitoring`)

### 2.1 Flow ผู้ใช้
1. กรอง Project / Media Type / Zone → เห็นจำนวนป้ายที่จะวางแผนแบบสด
2. ใส่เงื่อนไข: จำนวนพนักงาน, จำนวนวัน, จุดเริ่มต้น, นาที/ป้าย (ค่าเริ่ม 5), ความเร็วเฉลี่ย (22 กม./ชม.), เพดาน 8 ชม./วัน
3. เลือก **เกณฑ์แบ่งงาน**: *ยุติธรรมด้วยชั่วโมงงาน (ค่าเริ่มต้น)* หรือ *เท่ากันด้วยจำนวนป้าย*
4. เลือกออปชันเส้นทาง (เลี่ยงทางด่วน/ทางพิเศษ ฯลฯ) แล้วกด **Run Routing Plan** → มี Progress แสดงระหว่างคำนวณ
5. ผลลัพธ์: การ์ดสรุปต่อคน/ต่อวัน (จำนวนป้าย, กม., ชั่วโมง), เส้นทางบนแผนที่พร้อมลูกศรทิศทางและหมายเลขลำดับ, รายการหยุดพร้อมระยะ/เวลาระหว่างจุด
6. จำลองเหตุฉุกเฉิน (พนักงานลา) → ระบบเกลี่ยงานใหม่และแสดงผลกระทบชั่วโมงงาน
7. บันทึกแผนลง `map_saved_routes`, โหลดกลับ, Export CSV/GPX/KML/Google Maps URL

### 2.2 Flow ระบบ (ทีละขั้น)
1. **ดึงข้อมูล** — ใช้ `listAssetsForMap` ชุดเดียวกับ Asset Map (ไม่ query ซ้ำ) + `listAssetRiskScores`
2. **กรอง** — ตัดป้ายที่ไม่มีพิกัด/ไม่ตรงตัวกรองออกในเบราว์เซอร์
3. **แบ่งพื้นที่รับผิดชอบ (Zoning)** — K-Means++ บนพิกัด (deterministic seed → ผลเหมือนเดิมทุกครั้งที่กดซ้ำ) แล้วเกลี่ยภาระ:
   - โหมด *จำนวนป้าย*: `clusterBalanced` ย้ายป้ายที่ "ย้ายแล้วเสียระยะน้อยที่สุด" จากโซนหนักไปโซนเบา จนต่างกัน ≤ 8%
   - โหมด *ยุติธรรม*: `clusterFairHours` คำนวณ (เวลาตรวจ + เวลาขับโดยประมาณ) ของแต่ละโซน แล้วถ่วงน้ำหนักและจัดกลุ่มซ้ำหลายรอบ → คนที่พื้นที่กระจายจะได้ป้ายน้อยลงโดยอัตโนมัติ
4. **จัดสรรคน** — `allocateProportional` (largest remainder) กระจายพนักงานตามปริมาณงานจริงของแต่ละพื้นที่
5. **แบ่งวัน** — `splitIntoDaysFair` / `splitIntoDaysBalanced` แตกงานของแต่ละคนเป็น N วันตามความใกล้กันเชิงพื้นที่ แล้วเรียงวันตามแนวตะวันตก→ตะวันออก เพื่อลดการวิ่งย้อน
6. **เรียงตามความเสี่ยง** — `sortDaysByRisk` ใช้น้ำหนัก high=3 / medium=1 / low=0 ดันวันที่มีป้ายเสี่ยงสูงไปอยู่ต้นรอบ (โซนและภาระงานไม่เปลี่ยน)
7. **หาเส้นทางจริง** — `computeDayRoute`: เรียงต้นทางด้วย nearest-neighbour → ส่ง OSRM `/trip` ทีละก้อน ≤ 60 จุด (และ `/route` ≤ 90 จุด) → ต่อก้อนเข้าด้วยกัน → ถ้า OSRM ล่ม ระบบ fallback เป็นระยะเส้นตรง และติดธง `approximate`
8. **สรุปผล** — ต่อวัน: ระยะรวม, เวลาขับ, เวลาตรวจ (นาที/ป้าย × จำนวนป้าย), ชั่วโมงงานรวมเทียบเพดาน 8 ชม.
9. **บันทึก/Export** — เก็บทั้งแผน (ตัวกรอง + โหมด + ผลลัพธ์) เป็น payload เดียวใน `map_saved_routes`

### 2.3 คะแนนความเสี่ยง (`asset_risk_scores`) — คำนวณอัตโนมัติในฐานข้อมูล
สูตร (เต็ม 100 คะแนน) ในฟังก์ชัน `recompute_asset_risk_scores`:

| องค์ประกอบ | น้ำหนัก | ตรรกะ |
|---|---|---|
| มีเคลมค้างเปิด | 40 | มี = เต็ม |
| เคลม 30 วัน | 25 | นับสูงสุด 2 ครั้ง |
| เคลม 90 วัน | 15 | นับสูงสุด 4 ครั้ง |
| เคลม 365 วัน | 10 | นับสูงสุด 8 ครั้ง |
| วันตั้งแต่ PM ล่าสุด | 10 | นับสูงสุด 180 วัน |

ระดับ: ≥60 = สูง, 25–59 = กลาง, <25 = ต่ำ
พร้อมเก็บ "หมวดปัญหาที่พบซ้ำมากที่สุด" ใน 1 ปีย้อนหลัง เพื่อใช้เป็นคำแนะนำการตรวจ
ดูรายละเอียดรายป้ายพร้อมกราฟได้ที่เมนู **คะแนนความเสี่ยง** (`/risk-score`)

## 3. AI และระบบอัตโนมัติอยู่ตรงไหน

**อัตโนมัติ (ไม่ต้องมีคนสั่ง)**
- Sync ข้อมูลจาก MSSQL รายวันด้วย cron: assets, PM schedules, asset history
- คำนวณคะแนนความเสี่ยงใหม่ทุกคืน (`recompute_asset_risk_scores`)
- รีเฟรชตารางสรุป PM/Claim (`refresh_pm_views`)
- จัดโซน/แบ่งวัน/จัดลำดับเส้นทาง — คำนวณให้ทั้งหมดเมื่อกดปุ่มเดียว
- เกลี่ยงานใหม่อัตโนมัติเมื่อระบุพนักงานลา

**AI (Lovable AI Gateway)** — ใช้เฉพาะงานที่ต้องตีความ ไม่ใช่การจัดเส้นทาง
- วิเคราะห์ทำเลป้าย/บริบทโดยรอบ และสรุปเชิงบรรยายในหน้า Analytics/Mockup (ปรับ Prompt ได้เองในหน้าตั้งค่า)
- จำแนกสาเหตุปัญหา (RCA) จากข้อความประวัติงานซ่อม

**สิ่งที่ *ไม่* ใช้ AI โดยเจตนา** — Zoning, TSP, ระยะทาง, คะแนนความเสี่ยง ทั้งหมดเป็นอัลกอริทึม deterministic
ข้อดี: ผลลัพธ์ตรวจสอบย้อนกลับได้, ทำซ้ำได้เหมือนเดิม, ต้นทุนคงที่, ไม่มี hallucination

## 4. Benefit — ตอบโจทย์ใคร

| กลุ่มผู้ใช้ | Asset Map | Route Monitoring |
|---|---|---|
| **Sales / CRM** | หาป้ายใกล้ทำเลที่ลูกค้าสนใจใน 10 วินาที, Mockup + Street View, แชร์ลิงก์/Export PPTX–PDF ให้ลูกค้าได้ทันที | – (ซ่อนข้อมูลงานซ่อมจากทีมพาณิชย์ตามนโยบายสิทธิ์) |
| **Operation / ทีมตรวจ** | ตรวจสภาพจริงผ่าน Street View ก่อนออกหน้างาน | แผนงานรายคน/รายวันพร้อมลำดับหยุดและเวลา ลดการวางแผนด้วยมือ |
| **หัวหน้างาน / Planner** | มองภาพรวมสถานะป้ายทั้งพอร์ตบนแผนที่เดียว | แบ่งงานยุติธรรมวัดผลได้, จำลองสถานการณ์คนลาได้ทันที |
| **ผู้บริหาร** | เห็นการกระจายสินทรัพย์เชิงพื้นที่ | เห็นชั่วโมงงาน/ระยะทางที่ลดลง, ป้ายเสี่ยงสูงถูกตรวจก่อน = ลด downtime ที่กระทบรายได้ |

**ผลลัพธ์เชิงตัวเลขที่วัดได้**
- ลดระยะทาง/ค่าน้ำมันจากการจัดเส้นทางแบบ TSP เทียบกับการวิ่งตามลำดับรายชื่อ
- ลดเวลาวางแผนจากหลักชั่วโมง/สัปดาห์ เหลือหลักนาที
- ความต่างของชั่วโมงงานระหว่างพนักงาน ≤ 8%
- ป้ายเสี่ยงสูงถูกตรวจในช่วงต้นรอบเสมอ → ลดเวลาป้ายดับ/ค่าปรับลูกค้า

## 5. ต่อยอดได้อีก

**ระยะสั้น**
1. เพดานชั่วโมงจริงต่อวัน + ตัดป้ายเสี่ยงต่ำออกอัตโนมัติเมื่อเกิน แล้วดันเป็นคิวแรกรอบถัดไป (Phase 6 ที่วางไว้)
2. คลังสินค้า/จุดตั้งต้นจริงของแต่ละทีม แทนจุดกึ่งกลางโซน
3. Export แผนงานเข้า Google Maps / นำเข้าแอปมือถือของช่างโดยตรง

**ระยะกลาง**
4. เช็คอินหน้างานด้วย GPS + ถ่ายรูป → เทียบแผนกับงานที่ทำจริง (Plan vs Actual)
5. เวลาเดินทางที่คิดสภาพจราจรจริงรายช่วงเวลา (Google Routes / traffic-aware)
6. ต้นทุนต่อรอบตรวจ (น้ำมัน + ค่าแรง) และเปรียบเทียบสถานการณ์ 3–5 แผนพร้อมกัน

**ระยะยาว**
7. พยากรณ์การเสียล่วงหน้าจากประวัติเคลม (predictive maintenance) แทนคะแนนแบบ rule-based
8. จัดตารางอัตโนมัติรายสัปดาห์และส่งแผนให้ทีมเองทุกเช้าวันจันทร์
9. เชื่อมข้อมูล traffic/foot-traffic เข้ากับมูลค่าเชิงพาณิชย์ของป้าย เพื่อจัดลำดับความสำคัญด้วย "ผลกระทบต่อรายได้" ไม่ใช่แค่ความเสี่ยงเชิงเทคนิค
